## 남은 확인 사항

- **유상운송 (출시 전 필수):** 기름값을 넘는 “운전 노동비” 정산을 돕고 광고 수익을 내는 서비스가 여객자동차운수사업법상 유상운송 알선으로 해석될 여지가 있는지 법률 확인. 영수증 표현은 “요금”이 아닌 “수고비”로 통일.
- **광고 (출시 전):** 카카오 애드핏 매체 심사 기준(도구형 앱의 콘텐츠 품질), 구글 애드센스의 도메인 조건, 광고 카드 닫기 버튼·하단 배치의 정책 적합성, 개인정보처리방침의 광고 관련 고지와 맞춤형 광고 동의 필요 여부, 광고 수익 소득 신고.
- **송금 링크 (출시 직후 기능 전):** 토스·카카오페이 송금 링크의 형식, 금액 자동 입력 지원 여부.
- **위치정보법 (출시 전 필수):** 운전 중 잠금의 폰 내부 속도 감지와, 사용자가 고른 장소 좌표를 서버가 중계하는 것이 위치정보 수집·이용 신고나 동의 대상인지 전문가 확인. 해당하면 동의 화면 추가 또는 기능 조정.
- **기술 확인:** “개발 초기에 확인할 위험” 목록(오피넷 해외 IP 차단 여부, 카카오모빌리티 결제수단 없을 때 초과분 처리, Rate Limiting 바인딩 무료 플랜 사용 가능 여부, 오피넷 이용 조건).
- **TMAP 예비 (개발 착수 전):** Free 요금제를 결제수단 없이 쓸 수 있는지, 응답 캐시·가공 표시 허용 범위(카카오 포함), 도로별 교통 정보를 받는 방식.
- **M3 구현 후 (M6 실제 키 테스트 전):**
  - 카카오모빌리티 `traffic_state`(0 없음·1 정체·2 지체·3 서행·4 원활·6 사고)와 TMAP 혼잡도(0 없음·1 원활·2 서행·3 지체·4 정체) 코드 정의를 각 사 문서로 확인. 다르면 `apps/worker/src/providers/kakao.ts`·`tmap.ts`의 코드 목록과 fixtures를 고친다.
  - 오피넷 API 키의 실제 일일 호출 한도·이용 조건. 하드 상한 50건이 한도 안인지.
  - workers.dev에서 Cache API가 정말 동작하지 않는지. 동작하거나 도메인을 사면 경로 캐시를 Cache API로 옮길지 다시 본다.
  - TMAP 경로·POI가 400을 주는 경우(출발·도착이 너무 가까움 등). 지금은 400을 "경로 없음"(422)으로 보고 예비로 넘어가지 않는다.
  - ~~Turnstile 검증 호출이 예산 카운터를 거치지 않음~~ → 해결(2026-09-18): 하루 20,000건 상한 추가. 알림 웹훅만 예외(위 "기본값" 결정).
- **공공 교통 이력 (2차 착수 전):** 한국도로공사·교통 빅데이터 플랫폼 데이터의 이용허락 범위(서비스 내 가공 표시 가능 여부), 자동 다운로드 허용 여부, 카카오 도로 이름과 도로공사 노선명 매칭 정확도.


## 비즈니스 모델

기능은 전부 무료이고, 수익은 “계산을 등록하면 광고 1번” 하나입니다. 결제, 구독, 송금 수수료는 없습니다. 광고는 사용 흐름을 절대 막지 않는다는 원칙을 우선합니다.

### 광고 규칙

| 항목             | 규칙                                                                                                    |
|------------------|---------------------------------------------------------------------------------------------------------|
| 트리거           | 도착 후 “정산하기”로 계산을 처음 등록할 때 광고 1번 요청                                                |
| 빈도             | 여행 1건당 1번. 수정 후 재등록, 지난 여행 다시 보기, 링크 재공유에는 표시하지 않음(폰에 표시 여부 저장) |
| 위치             | 정산 결과 화면(S10) 스크롤 맨 아래, 계산 근거 다음. 결과 금액·보낼 돈 목록보다 항상 아래                |
| 형태             | 배너·네이티브 광고 카드 1개. “광고” 표시, 닫기(✕) 버튼                                                  |
| 기다림           | 없음. 결과는 즉시 표시하고 광고는 뒤에서 불러와 준비되면 맨 아래에 붙음                                 |
| 실패 시          | 아무것도 표시하지 않음. 빈 자리나 오류 문구 없음                                                        |
| 표시하지 않는 곳 | 여행 중 화면(S6~S8), 받는 사람 결과 페이지(S11), 결과 이미지·공유 문구                                  |

### 사용성을 지키는 장치

- **결과가 먼저:** 광고를 기다리는 대기 화면, 카운트다운, 전면 광고를 쓰지 않는다.
- **화면이 밀리지 않게:** 광고 카드는 콘텐츠 맨 끝에 붙기 때문에, 불러오는 순간에도 위의 금액·목록 위치가 움직이지 않는다.
- **실수 클릭 방지:** 광고 카드는 하단 “결과 링크 공유” 버튼과 겹치지 않도록 버튼 영역만큼 여백을 둔다. 광고 네트워크의 유도 클릭 금지 정책과도 맞다.
- **닫으면 끝:** ✕를 누르면 카드가 사라지고 이 여행에서는 다시 나오지 않는다.
- **소리·움직임 없음:** 자동 재생 동영상, 소리 나는 광고 형식은 쓰지 않는다. 야간 모드에서는 카드 테두리와 배경을 어둡게 한다.

### 광고 네트워크 현실 (확인 필요)

- **웹에 맞는 형식:** 결과 화면 안의 카드 광고는 웹(PWA)에서 쓸 수 있는 배너·네이티브 광고와 잘 맞는다. 카카오 애드핏은 배너·네이티브 광고를 제공하고, 실행·화면 전환 팝업 광고는 앱 전용 상품이다.
- **매체 심사:** 애드핏은 매체 소유관계, 콘텐츠의 질적·양적 품질, 트래픽 품질을 심사한다. 도구형 앱은 불리할 수 있어 서비스 소개·사용 가이드·계산 방법 설명 페이지를 함께 준비한다.
- **도메인:** 구글 애드센스는 상위 도메인 기준으로 승인받는 것이 일반적이라 workers.dev 주소로는 어려울 가능성이 높다. 자체 도메인 구입(연 1만 원대)이 첫 지출이 될 수 있다.
- **닫기 버튼과 노출 기준:** 광고 카드에 닫기 버튼을 두는 것과 화면 맨 아래 배치가 광고 네트워크 정책·노출 집계 기준에 맞는지 확인한다.

### 개인정보와 보안

- 광고 스크립트는 S10의 광고 카드에서만 불러온다. 결과 보기 페이지(/r)는 CSP로 외부 스크립트를 막는다.
- 광고 네트워크는 쿠키·기기 정보를 직접 수집할 수 있으므로 개인정보처리방침에 고지하고, 맞춤형 광고 동의가 필요한지 확인한다.
- 광고 요청에 이름·금액·목적지 같은 여행 정보를 넣지 않는다. 서버 최소 정보 원칙은 그대로다.

### 기대 수익과 다음 단계

여행 때만 쓰는 앱이고 광고가 화면 맨 아래에 있어, 노출 수와 광고 단가 모두 높지 않을 것입니다. 사용성을 우선한 선택이며, 초기 목표는 도메인·운영 비용을 덮는 수준입니다. 수익을 키우는 방안은 사용자 반응을 본 뒤 판단하고, 그 전에 유상운송 쟁점 확인이 선행되어야 합니다.

### 출시 형태와 코드 구조

PWA로 먼저 출시하고, 나중에 네이티브로 옮길 때 다시 만들지 않도록 화면과 로직을 분리한 모노레포로 시작합니다.

    driver-labor/
    ├── CLAUDE.md, docs/          ← Claude Code용 규칙과 기획 문서
    ├── packages/calc             ← 계산 엔진: 구간 자동 생성, 유류비, 노동비, 난이도, 괘씸, 정산 (순수 함수)
    ├── packages/link-codec       ← 결과 링크 압축·해제·검증
    ├── packages/storage          ← 저장소 인터페이스 (웹: IndexedDB, 네이티브: SQLite로 교체)
    ├── apps/web                  ← PWA 앱 (Vite + React + TypeScript)
    ├── apps/result               ← 결과 보기 정적 페이지 (외부 스크립트 없음)
    ├── apps/worker               ← Cloudflare Worker (/api 중계, 정적 자산 서빙)
    └── fixtures/                 ← 카카오·TMAP·오피넷 샘플 응답 (실제 키 없이 개발)

- **계산 엔진 공유:** 앱, 결과 페이지, 나중의 네이티브 앱이 같은 계산 코드를 쓴다. 기획서의 계산 예시를 단위 테스트로 고정한다.
- **화면만 교체:** 네이티브 전환 시 새로 만드는 것은 apps/mobile의 화면과 저장소 구현뿐이다.
- **결과 페이지는 계속 웹:** 링크를 받은 사람은 앱이 없으므로 네이티브 전환 후에도 apps/result는 유지한다.

### 네이티브 전환 조건

아래 중 하나라도 해당하면 네이티브 전환을 검토합니다. 수치 기준은 출시 후 실제 사용량을 보고 정합니다.

- **광고:** 웹 광고 네트워크 승인을 받지 못하거나, 웹 광고 수익이 도메인·운영 비용을 덮지 못함. 네이티브는 앱 광고 SDK를 쓸 수 있다.
- **재사용:** 같은 사용자가 반복해서 여행을 등록해 “홈 화면 아이콘·스토어 설치” 가치가 커짐.
- **기능 한계:** 운전 중 잠금의 속도 감지 불안정, 기기 내부 음성 인식 요구 등 PWA로 해결할 수 없는 요구가 반복됨.

전환 시 추가 비용: 구글 플레이 개발자 등록 1회 25달러, 애플 개발자 프로그램 연 99달러. iOS 맞춤형 광고는 추적 동의 창(ATT)이 필요하므로 비맞춤형 광고로 시작한다.
