## 남은 확인 사항

- **유상운송 (출시 전 필수):** 기름값을 넘는 “운전 노동비” 정산을 돕고 광고 수익을 내는 서비스가 여객자동차운수사업법상 유상운송 알선으로 해석될 여지가 있는지 법률 확인. 영수증 표현은 “요금”이 아닌 “수고비”로 통일.
- **광고 (출시 전):** 카카오 애드핏 매체 심사 기준(도구형 앱의 콘텐츠 품질), 구글 애드센스의 도메인 조건, 광고 카드 닫기 버튼·하단 배치의 정책 적합성, 개인정보처리방침의 광고 관련 고지와 맞춤형 광고 동의 필요 여부, 광고 수익 소득 신고.
- **송금 링크 (출시 직후 기능 전):** 토스·카카오페이 송금 링크의 형식, 금액 자동 입력 지원 여부.
- **위치정보법 (앱 출시 전 필수):** 운전 중 잠금의 폰 내부 속도 감지와, 사용자가 고른 장소 좌표를 서버가 중계하는 것이 위치정보 수집·이용 신고나 동의 대상인지 전문가 확인. 앱은 위치 권한을 요청하므로 고지 문구와 동의 화면 문안까지 정해야 한다(위치가 폰 밖으로 나가지 않는다는 설명 포함).
- **앱 출시 준비 (사람이 해야 함):**
  - Play 개발자 계정 등록(25달러, 1회). TypeRight·무모한 시식가와 같은 계정을 쓴다.
  - 개인 계정은 프로덕션 신청 전 클로즈드 테스트 12명 × 14일 연속이 필요하다. 테스터 모집과 일정.
  - 스토어 등록정보: 아이콘, 스크린샷, 짧은·긴 설명, 콘텐츠 등급 설문, 광고 포함 표시, 데이터 보안 양식(위치·광고 식별자), 개인정보처리방침 URL.
  - AdMob 계정과 광고 단위 ID 발급, app-ads.txt 필요 여부 확인.
  - Play Console이 요구하는 targetSdk 수준 확인. 지금은 Capacitor 기본값(minSdk 24 / compileSdk·targetSdk 36)으로 에뮬레이터 Android 15에서 동작을 확인했다.
  - Turnstile 위젯 호스트에 WebView 출처(`localhost`) 등록. 앱 위조 대응으로 Play Integrity로 바꿀지는 출시 뒤 재검토.
- **기술 확인:** “개발 초기에 확인할 위험” 목록(오피넷 해외 IP 차단 여부, 카카오모빌리티 결제수단 없을 때 초과분 처리, Rate Limiting 바인딩 무료 플랜 사용 가능 여부, 오피넷 이용 조건).
- **TMAP 예비 (개발 착수 전):** Free 요금제를 결제수단 없이 쓸 수 있는지, 응답 캐시·가공 표시 허용 범위(카카오 포함), 도로별 교통 정보를 받는 방식.
- **M3 구현 후 (M6 실제 키 테스트 전):**
  - 카카오모빌리티 `traffic_state`(0 없음·1 정체·2 지체·3 서행·4 원활·6 사고)와 TMAP 혼잡도(0 없음·1 원활·2 서행·3 지체·4 정체) 코드 정의를 각 사 문서로 확인. 다르면 `apps/worker/src/providers/kakao.ts`·`tmap.ts`의 코드 목록과 fixtures를 고친다.

## 비즈니스 모델

기능은 전부 무료이고, 수익은 “계산을 등록하면 광고 1번” 하나입니다. 결제, 구독, 송금 수수료는 없습니다. 광고는 사용 흐름을 절대 막지 않는다는 원칙을 우선합니다.

### 광고 규칙

| 항목             | 규칙                                                                                                    |
|------------------|---------------------------------------------------------------------------------------------------------|
| 트리거           | 도착 후 “정산하기”로 계산을 처음 등록할 때 광고 1번 요청                                                |
| 빈도             | 여행 1건당 1번. 수정 후 재등록, 지난 여행 다시 보기, 링크 재공유에는 표시하지 않음(폰에 표시 여부 저장) |
| 위치             | 정산 결과 화면(S10) 스크롤 맨 아래, 계산 근거 다음. 결과 금액·보낼 돈 목록보다 항상 아래                |
| 형태             | 배너·네이티브 광고 카드 1개. “광고” 표시, 닫기(✕) 버튼                                                  |
| 기다림           | 없음. 결과는 즉시 표시하고 광고는 뒤에서 불러와 준비되면 맨 아래에 붙음                                 |
| 실패 시          | 아무것도 표시하지 않음. 빈 자리나 오류 문구 없음                                                        |
| 표시하지 않는 곳 | 여행 중 화면(S6~S8), 받는 사람 결과 페이지(S11), 결과 이미지·공유 문구                                  |

### 사용성을 지키는 장치

- **결과가 먼저:** 광고를 기다리는 대기 화면, 카운트다운, 전면 광고를 쓰지 않는다.
- **화면이 밀리지 않게:** 광고 카드는 콘텐츠 맨 끝에 붙기 때문에, 불러오는 순간에도 위의 금액·목록 위치가 움직이지 않는다.
- **실수 클릭 방지:** 광고 카드는 하단 “결과 링크 공유” 버튼과 겹치지 않도록 버튼 영역만큼 여백을 둔다. 광고 네트워크의 유도 클릭 금지 정책과도 맞다.
- **닫으면 끝:** ✕를 누르면 카드가 사라지고 이 여행에서는 다시 나오지 않는다.
- **소리·움직임 없음:** 자동 재생 동영상, 소리 나는 광고 형식은 쓰지 않는다. 야간 모드에서는 카드 테두리와 배경을 어둡게 한다.

### 광고 네트워크 (AdMob, 2026-09-21 확정)

- **형식:** 결과 화면 맨 아래 배너 1개. 전면·보상형·자동 재생 광고는 쓰지 않는다. 광고 규칙 표는 그대로 지킨다.
- **승인:** AdMob은 앱 단위로 승인해서 도메인이 필요 없다. 애드핏 매체 심사와 애드센스 도메인 조건은 더 따지지 않는다.
- **비맞춤형으로 시작:** 동의 창(UMP)을 붙이기 전까지 비맞춤형 광고로 낸다. 광고 요청에 여행 정보를 넣지 않는 원칙은 그대로다.
- **닫기 버튼:** 카드의 닫기(✕)와 하단 배치가 AdMob 정책(광고 위치·오클릭 유도 금지)에 맞는지 구현할 때 확인한다.

### 개인정보와 보안

- 광고는 S10의 광고 카드에서만 부른다(앱은 AdMob SDK). 결과 보기 페이지(/r)는 CSP로 외부 스크립트를 막는다.
- 광고 네트워크는 쿠키·기기 정보를 직접 수집할 수 있으므로 개인정보처리방침에 고지하고, 맞춤형 광고 동의가 필요한지 확인한다.
- 광고 요청에 이름·금액·목적지 같은 여행 정보를 넣지 않는다. 서버 최소 정보 원칙은 그대로다.

### 기대 수익과 다음 단계

여행 때만 쓰는 앱이고 광고가 화면 맨 아래에 있어, 노출 수와 광고 단가 모두 높지 않을 것입니다. 사용성을 우선한 선택이며, 초기 목표는 Play 등록비와 운영 비용을 덮는 수준입니다. 수익을 키우는 방안은 사용자 반응을 본 뒤 판단하고, 그 전에 유상운송 쟁점 확인이 선행되어야 합니다.

### 출시 형태와 코드 구조

입력 담당은 안드로이드 앱(Capacitor), 링크를 받은 동승자는 웹입니다. 화면과 로직을 분리한 모노레포라 앱으로 옮기면서 화면 코드를 그대로 씁니다.

    driver-labor/
    ├── CLAUDE.md, docs/          ← Claude Code용 규칙과 기획 문서
    ├── packages/calc             ← 계산 엔진: 구간 자동 생성, 유류비, 노동비, 난이도, 괘씸, 정산 (순수 함수)
    ├── packages/link-codec       ← 결과 링크 압축·해제·검증
    ├── packages/storage          ← 저장소 인터페이스 (WebView IndexedDB 그대로 사용)
    ├── apps/web                  ← 앱 화면 (Vite + React + TypeScript). Capacitor가 그대로 담는다
    ├── apps/mobile               ← Capacitor 설정과 안드로이드 프로젝트 (M7에서 추가)
    ├── apps/result               ← 결과 보기 정적 페이지 (외부 스크립트 없음, 계속 웹)
    ├── apps/worker               ← Cloudflare Worker (/api 중계, /r과 소개·정책 페이지 서빙)
    └── fixtures/                 ← 카카오·TMAP·오피넷 샘플 응답 (실제 키 없이 개발)

- **계산 엔진 공유:** 앱과 결과 페이지가 같은 계산 코드를 쓴다. 기획서의 계산 예시를 단위 테스트로 고정한다.
- **화면은 하나:** 앱 화면은 `apps/web`의 React 화면 그대로다. 네이티브 기능(위치·공유·광고)만 Capacitor 플러그인으로 연결한다.
- **결과 페이지는 계속 웹:** 링크를 받은 사람은 앱이 없다. `apps/result`는 앱 전환과 무관하게 그대로다.
- **웹 배포는 멈춘다:** 입력 담당 화면을 웹 주소로 열어 쓰게 하지 않는다. Worker `/`는 소개·사용 가이드·개인정보처리방침 정적 페이지가 된다.
- **앱에서 달라지는 연결:** 화면이 `https://localhost`에서 뜨므로 `/api`는 절대 주소이고 Worker에 CORS 허용이 필요하다. 결과 링크 주소도 `location.origin` 대신 배포 주소 상수를 쓴다.

### 앱 전환 비용과 일정 요인

- 구글 플레이 개발자 등록 1회 25달러(TypeRight·무모한 시식가와 계정 공용). 그 밖에 늘어나는 고정비는 없다.
- 개인 개발자 계정은 프로덕션 전에 클로즈드 테스트 12명 × 14일 연속이 필요해 출시 일정에 2주 이상을 잡는다.
- 업데이트가 심사 통과 뒤에 나간다. 계산·문구 수정도 릴리스 단위가 된다. 원격으로 화면 코드를 내려받아 바꾸는 방식은 정책 위험이 있어 쓰지 않는다.
- iOS는 범위 밖이다. 하게 되면 같은 코드에 iOS 프로젝트만 더한다(연 99달러, ATT 때문에 비맞춤형 광고로 시작).
