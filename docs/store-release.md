## 0-1. 방침 URL을 어떻게 띄울까 (판단)

스토어에 넣을 개인정보처리방침은 **공개 URL이어야 하고 내부 테스트 업로드 전에 필요하다.** 이 저장소는 Worker `/`에 두기로 돼 있어 Worker 배포가 선행 조건이 된다.

| 방법 | 장점 | 단점 |
|---|---|---|
| **A. Worker 배포(추천)** | 주소가 하나로 모인다(`/privacy`, `/r`, `/api`). 앱의 API 주소·결과 링크 주소도 이때 확정된다. 무료 | 사람 승인과 Cloudflare 계정 작업이 필요 |
| B. GitHub Pages에 방침만 | Cloudflare 없이 바로 띄운다(TypeRight와 같은 방식) | 주소가 둘로 갈린다. 결과 링크는 어차피 Worker가 필요해 두 번 일한다 |

**A를 권한다.** 이유는 세 가지다.

1. Worker는 방침 때문이 아니라 **앱이 동작하려면 어차피 필요하다.** 장소 검색·경로·유가 조회가 전부 Worker를 거친다.
2. **secret 없이 배포해도 방침 페이지는 뜬다.** 정적 자산은 키와 무관하고, `/api`만 503으로 응답한다. 즉 "방침 URL 확보"와 "실제 키 통합 테스트"를 분리할 수 있다.
3. 배포하면 `VITE_API_BASE`·`VITE_RESULT_BASE`·`ALLOWED_ORIGINS`·Turnstile 호스트가 한 번에 확정돼, 내부 테스트에 올릴 AAB를 제대로 만들 수 있다. 지금 AAB를 만들면 API 주소가 비어 있어 자동 조회가 되지 않는다.

배포 순서와 확인 절차는 `docs/deploy.md`에 있다. ① 페이지만 배포(외부 API 키 없이) → ② 방침 URL 확정 → ③ 키를 받으면 secret 등록 → ④ 실제 조회 확인. ①만 해도 내부 테스트 업로드를 막는 조건은 풀린다. **①은 사람 승인이 필요하다.**

## 1. 업로드 키스토어

### 사람이 하는 일

1. 키스토어를 만든다. 비밀번호 두 개(키스토어·키)를 정해 비밀번호 관리자에 넣는다.

   ```bash
   keytool -genkeypair -v -keystore driver-labor-upload.jks \
     -alias driver-labor -keyalg RSA -keysize 4096 -validity 10000
   ```

2. `driver-labor-upload.jks`는 **저장소에 넣지 않는다.** `~/keys/driver-labor/` 같은 홈 아래 폴더에 두고, 비밀번호 관리자에도 파일을 백업한다.
3. 비밀번호는 `~/.gradle/gradle.properties`에만 적는다(저장소 밖, 사용자 홈).

   ```properties
   DL_UPLOAD_STORE_FILE=/Users/<사용자>/keys/driver-labor/driver-labor-upload.jks
   DL_UPLOAD_STORE_PASSWORD=…
   DL_UPLOAD_KEY_ALIAS=driver-labor
   DL_UPLOAD_KEY_PASSWORD=…
   ```

4. Play Console에서 앱을 만들 때 **Play 앱 서명**을 켠다(새 앱은 기본값).

### 지금 상태 (2026-09-21)

- 키스토어: `~/keys/driverlabor-upload.jks`, 별칭 `driverlabor` (RSA 2048, 10000일). 저장소 밖이다.
- `~/.gradle/gradle.properties`에 네 값을 넣어 연결했다. **비밀번호는 문서·로그·커밋 어디에도 적지 않는다.**
- 서명된 AAB를 만들어 지문을 대조했다(아래 "검증" 참고).

| 항목 | 값 |
|---|---|
| 산출물 | `apps/mobile/android/app/build/outputs/bundle/release/app-release.aab` |
| 크기 | 약 3.0MB (3,130,644 바이트) |
| versionCode / versionName | 1 / 1.0.0 (`apps/mobile/version.json`) |
| 서명 인증서 | `CN=driverlabor, OU=Personal, O=Personal, L=Seoul, ST=Seoul, C=KR` |
| SHA1 | `FD:97:ED:B6:5A:3E:8A:92:7F:5F:32:75:AC:B1:B6:6F:2A:B8:F5:80` (사람이 알려준 지문과 일치) |

### 검증

```bash
cd apps/mobile
pnpm run aab   # 릴리스 동기화 + bundleRelease
KT="/Applications/Android Studio.app/Contents/jbr/Contents/Home/bin/keytool"
"$KT" -printcert -jarfile android/app/build/outputs/bundle/release/app-release.aab | grep -E "소유자|SHA1"
```

SHA1이 업로드 키의 지문과 같아야 한다. 다르면 `gradle.properties` 값이 안 잡힌 것이고,
그 경우 서명 없이 빌드되므로 Play가 업로드를 거부한다(`META-INF/*.RSA`가 없으면 미서명이다).

### 코드로 하는 일

- `apps/mobile/android/app/build.gradle`에 release `signingConfig`를 더한다. 값은 위 `gradle.properties`에서 읽고, 값이 없으면 서명 없이 빌드한다(다른 사람이 받아도 빌드는 된다).
- `.gitignore`에 `*.jks`, `*.keystore`, `keystore.properties`를 더한다.
- 확인 방법: 서명한 AAB를 만들고 `jarsigner -verify`나 Play Console 업로드로 확인한다.

### 잃어버리면

- **업로드 키**를 잃어버려도 Play 앱 서명을 켰다면 구글에 새 업로드 키 등록을 요청할 수 있다. 검토에 며칠 걸린다.
- **Play 앱 서명을 켜지 않은 채 앱 서명 키를 잃어버리면 같은 앱으로 업데이트를 낼 수 없다.** 패키지명을 바꿔 새 앱으로 다시 올려야 하고, 설치된 사용자는 옮겨오지 못한다. 그래서 Play 앱 서명을 반드시 켠다.
- 어느 쪽이든 키스토어 파일과 비밀번호는 서로 다른 곳에 백업한다.

### 스크린샷 구성안

내부 테스트 업로드에는 2장이면 되고, 프로덕션 전에 4장으로 늘린다. 에이전트가 에뮬레이터
(Pixel 6, 1080×2400)에서 뽑는다.

**Play는 장변이 단변의 2배를 넘는 이미지를 받지 않는다.** 에뮬레이터 화면은 2400 ÷ 1080 = 2.22라
그대로는 못 올린다. 축소해도 비율은 그대로이므로 **잘라서 1080×1920(1.78)으로 맞춘다.**
`node apps/mobile/scripts/store-shot.mjs <이름> [위쪽 잘라낼 픽셀]`이 찍기와 자르기를 한 번에 한다.
하단 버튼이 잘리면 두 번째 인자로 위쪽 여백을 더 버린다.

| 순서 | 화면 | 담을 것 | 우선순위 |
|---|---|---|---|
| 1 | 홈(진행 중) | 큰 "완료" 버튼과 경과 시간. 이 앱이 미터기라는 걸 한 장으로 보여준다 | 내부 테스트 |
| 2 | 정산 결과 | 받을 돈(큰 숫자), 보낼 돈, 괘씸 사유 한 줄 | 내부 테스트 |
| 3 | 도착 요약 | 운전 시간, 도착지 입력, 난이도 | 프로덕션 |
| 4 | 괘씸·감면 입력 | 타일과 분 입력 | 프로덕션 |

- 데이터는 실제로 앱을 조작해 만든다(경포해변 · 2명 · 괘씸 2건). 가짜 합성 이미지를 만들지 않는다.
- **문구(캡션)는 넣지 않는다(확정).** 이미지에 글자를 덧입히면 "오해를 주는 스크린샷"이 될 여지가 있고 폰트 관리가 늘어난다. 설명은 짧은 설명·자세한 설명이 맡는다.
- **배포 뒤에 찍는다.** 앱 빌드에 서버 주소가 들어가야 장소 검색 결과나 "조회: 카카오" 같은 화면이 나온다. 실제 API 키가 없는 동안에는 조회가 실패하므로, 조회가 필요한 화면은 키를 받은 뒤 다시 찍는다.
- 상태바의 시계·배터리는 그대로 둔다(에뮬레이터 기본값). 개인 정보가 들어가지 않는다.
- 야간 모드 스크린샷은 넣지 않는다. 같은 화면이 두 번 보이는 것보다 다른 화면을 보여주는 편이 낫다.

## 2-1. 앱 링크(App Links) — 해당 없음

**결과 링크는 앱이 가로채지 않는다.** `assetlinks.json`도, `autoVerify` 인텐트 필터도 두지 않는다.
지금 매니페스트에는 런처 인텐트 필터 하나뿐이고 `VIEW` 필터가 없다.

이유는 두 가지다.

- 링크를 받는 사람은 앱이 없다. 브라우저에서 바로 열리는 것이 이 링크의 목적이다.
- 보낸 사람 폰에서 앱이 링크를 가로채면, 자기 결과를 다시 확인하려다 앱으로 튕겨 혼란스럽다.

**나중에 앱 링크를 붙이게 되면** 검증에 넣을 지문은 업로드 키가 아니라
**Play Console → 설정 → 앱 서명의 "앱 서명 키 SHA-256"**이다. Play 앱 서명을 켜면 구글이 업로드
빌드를 자기 키로 다시 서명하므로, 업로드 키 지문(`FD:97:…`)을 넣으면 링크 검증이 실패한다.
그때는 아래 "사람 확인 사항"에 이 항목을 되살린다.

## 3. 데이터 보안 양식

이 앱이 실제로 하는 것만 적는다. 위치·광고 식별자·계정·연락처는 쓰지 않는다.

| 질문 | 답 | 근거 |
|---|---|---|
| 데이터를 수집하거나 공유하나요 | **예** | 장소 검색어와 사용자가 고른 장소의 좌표가 우리 Worker를 거쳐 카카오·TMAP으로 간다 |
| 위치 | **아니요** | 기기 위치 권한을 요청하지 않는다. 좌표는 사용자가 목록에서 고른 장소의 것이다 |
| 개인 정보(이름·이메일·전화) | 아니요 | 멤버 이름은 폰에만 저장한다 |
| 금융 정보 | 아니요 | 금액은 폰에만 저장하고 결과 링크 안에만 들어간다 |
| 앱 활동(검색어) | **예 — 수집함** | 장소 검색어를 조회에 쓴다. 서버에 저장하지는 않지만 앱 밖으로 나가므로 수집으로 신고한다 |
| 앱 정보·성능(고른 장소 좌표) | **예 — 수집함** | 경로 조회에 쓴다. 기기 위치가 아니라 사용자가 목록에서 고른 장소의 좌표다 |
| 기기 식별자·광고 ID | 아니요 | 광고 SDK가 없다 |
| 데이터 암호화 전송 | 예 | HTTPS |
| 삭제 요청 방법 | 앱 삭제 | 서버에 사용자 데이터가 없다 |

**확정(2026-09-21): 검색어와 고른 장소 좌표를 "수집함"으로 신고한다.** 서버에 저장하지 않아도 앱 밖으로 나가기 때문이다. 신고 누락은 앱 정지 사유이고, 넉넉히 신고해서 받는 불이익은 없다.

"일시적 처리" 예외는 주장하지 않는다. 경로 응답을 6시간 캐시하기 때문이다(캐시 키는 반올림한 좌표를 비밀 값과 섞은 해시라 좌표 원문은 남지 않지만, 조회 결과 자체는 그 시간 동안 서버에 남는다). 장소 검색은 캐시하지 않지만, 두 값을 따로 신고해 헷갈리게 만들 이유가 없어 같이 신고한다.

폼에서 함께 고를 것: 전송은 암호화(HTTPS), 수집은 **선택 사항이 아님**(앱 기능에 필요), 삭제 요청 방법은 앱 삭제.

## 4. 개인정보처리방침 초안

페이지는 `apps/site/privacy.html`로 만들었고 Worker가 `/privacy`로 서빙한다. 주소는 `https://driver-labor.<계정>.workers.dev/privacy`(Worker 이름 `driver-labor` 확정). 시행일은 2026-09-21, 문의 이메일은 musikga1116@gmail.com(세 앱 공용)으로 채웠다. 실제 공개일이 다르면 시행일만 고친다.

1. **개요** — "오늘 운전 완료"는 로그인이 없고, 여행 기록을 서버에 저장하지 않습니다.
2. **폰에만 저장하는 것** — 여행 날짜·시각, 도착지 이름, 멤버 이름, 금액, 괘씸·결제 기록, 설정. 앱을 지우면 함께 사라지고 백업 기능은 제공하지 않습니다.
3. **서버로 전송하는 것과 이유**
   - 장소 검색어: 장소를 찾기 위해. 서버에 저장하지 않습니다.
   - 사용자가 고른 장소의 좌표: 거리·통행료·택시요금을 조회하기 위해. 캐시 키는 좌표를 비밀 값과 섞은 해시라 좌표 원문이 남지 않습니다.
   - 시·도 코드와 유종: 지역 평균 유가를 읽기 위해.
   - 사람 확인 토큰(Cloudflare Turnstile): 자동 프로그램의 남용을 막기 위해.
   - 위 값은 외부 조회 서비스(카카오모빌리티·카카오 로컬·TMAP·한국석유공사 오피넷)에 전달됩니다. 사용자 IP는 전달되지 않습니다.
4. **수집하지 않는 것** — 기기 위치, 연락처, 계정, 광고 식별자, 결제 정보. 광고를 넣지 않습니다.
5. **보관 기간** — 서버는 사용자 데이터를 보관하지 않습니다. 조회 응답 캐시는 최대 6시간이며 개인을 알아볼 수 없습니다. 오류 로그에는 오류 코드만 남깁니다.
6. **결과 링크** — 금액·이름은 링크 주소의 `#` 뒤에 담깁니다. 이 부분은 브라우저가 서버로 보내지 않습니다. 링크를 받은 사람은 앱 없이 볼 수 있으므로, 링크 공유 범위는 사용자가 정합니다.
7. **아동** — 만 14세 미만을 대상으로 하지 않습니다.
8. **권리와 문의** — 서버에 개인정보가 없어 열람·정정·삭제 요청 대상이 없습니다. 앱 삭제로 모든 기록이 지워집니다. 문의 이메일은 M6에서 정합니다.
9. **변경 고지** — 방침이 바뀌면 이 페이지에 날짜와 함께 올립니다.
