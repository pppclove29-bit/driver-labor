# 스토어 출시 준비 (M12)

> Play 스토어에 "오늘 운전 완료"를 올리는 데 필요한 것들. 사람이 해야 하는 일과 코드로 하는 일을 나눠 적는다.
> 앱은 위치·광고·계정을 쓰지 않는다. 그래서 심사에 필요한 선언이 적다. 이 문서는 그 전제 위에 쓰였다.
>
> **기본 경로는 개인 계정 기준이다.** 조직(사업자) 계정이면 빠지는 항목은 "조직 계정이면"으로 따로 표시했다.
> 계정 유형은 아직 확인하지 못했다(decisions.md 남은 확인 사항).

## 1. 업로드 키스토어

### 사람이 하는 일

1. 키스토어를 만든다. 비밀번호 두 개(키스토어·키)를 정해 비밀번호 관리자에 넣는다.

   ```bash
   keytool -genkeypair -v -keystore driver-labor-upload.jks \
     -alias driver-labor -keyalg RSA -keysize 4096 -validity 10000
   ```

2. `driver-labor-upload.jks`는 **저장소에 넣지 않는다.** `~/keys/driver-labor/` 같은 홈 아래 폴더에 두고, 비밀번호 관리자에도 파일을 백업한다.
3. 비밀번호는 `~/.gradle/gradle.properties`에만 적는다(저장소 밖, 사용자 홈).

   ```properties
   DL_UPLOAD_STORE_FILE=/Users/<사용자>/keys/driver-labor/driver-labor-upload.jks
   DL_UPLOAD_STORE_PASSWORD=…
   DL_UPLOAD_KEY_ALIAS=driver-labor
   DL_UPLOAD_KEY_PASSWORD=…
   ```

4. Play Console에서 앱을 만들 때 **Play 앱 서명**을 켠다(새 앱은 기본값).

### 코드로 하는 일

- `apps/mobile/android/app/build.gradle`에 release `signingConfig`를 더한다. 값은 위 `gradle.properties`에서 읽고, 값이 없으면 서명 없이 빌드한다(다른 사람이 받아도 빌드는 된다).
- `.gitignore`에 `*.jks`, `*.keystore`, `keystore.properties`를 더한다.
- 확인 방법: 서명한 AAB를 만들고 `jarsigner -verify`나 Play Console 업로드로 확인한다.

### 잃어버리면

- **업로드 키**를 잃어버려도 Play 앱 서명을 켰다면 구글에 새 업로드 키 등록을 요청할 수 있다. 검토에 며칠 걸린다.
- **Play 앱 서명을 켜지 않은 채 앱 서명 키를 잃어버리면 같은 앱으로 업데이트를 낼 수 없다.** 패키지명을 바꿔 새 앱으로 다시 올려야 하고, 설치된 사용자는 옮겨오지 못한다. 그래서 Play 앱 서명을 반드시 켠다.
- 어느 쪽이든 키스토어 파일과 비밀번호는 서로 다른 곳에 백업한다.

### 짧은 설명 초안 (80자)

> 출발할 때 시작, 도착해서 완료. 기름값과 운전 수고비를 친구끼리 깔끔하게 나눠요.

### 자세한 설명 초안

> **운전한 사람만 손해 보지 않게.**
>
> 친구들과 차로 여행하면 기름값은 나누는데 운전은 한 사람이 다 합니다. 이 앱은 운전한 시간을 수고비로 계산해서, 기름값·통행료와 함께 한 번에 정산해 줍니다.
>
> **쓰는 법은 두 번 누르는 것이 전부예요.**
> - 출발할 때 "시작"을 누르고 폰을 덮으세요. 운전 중에는 화면을 볼 일이 없습니다.
> - 도착해서 "완료"를 누르고, 어디에 도착했는지와 몇 명이 탔는지만 알려 주세요.
> - 나머지는 앱이 계산합니다. 결과를 링크로 보내면 친구는 앱 없이 바로 봅니다.
>
> **무엇을 계산하나요**
> - 유류비: 지역 평균 유가와 연비로 계산합니다. 주유 기록을 넣으면 그 단가를 씁니다.
> - 통행료·택시 예상요금: 경로 조회로 채웁니다. 조회가 안 되면 직접 넣어도 됩니다.
> - 운전 수고비: 운전 시간 × 기준 시급. 야간·정체·연속 운전은 난이도로 반영합니다.
> - 괘씸모드(선택): 조수석에서 잤거나 혼자 먹은 사람에게 조금 더 받습니다. 도착한 뒤 다 같이 보며 넣고, 억울하면 그 자리에서 뺍니다.
>
> **기록은 폰에만 남습니다**
> - 로그인이 없습니다. 여행 기록·금액·이름은 이 폰에만 저장됩니다.
> - 서버로 가는 값은 장소 검색어, 고른 장소의 좌표, 시·도 코드, 사람 확인 토큰뿐입니다.
> - 기기 위치를 쓰지 않습니다. 위치 권한을 요청하지 않습니다.
> - 결과 링크의 금액과 이름은 링크 주소 안에 들어 있고, 서버로 전송되지 않습니다.
> - 광고가 없습니다.
>
> **이런 분께**
> - 장거리 여행에서 늘 운전대를 잡는 사람
> - "기름값만 n분의 1" 말고 수고를 반영하고 싶은 모임
> - 정산 이야기를 꺼내기 민망한 사람(영수증 말투를 고를 수 있습니다)
>
> 금액은 앱을 쓴 사람이 입력한 값 기준입니다. 송금 전에 서로 확인하세요.

### 스크린샷 초안 (4장)

1. 홈 — 큰 "시작" 버튼
2. 도착 요약 — 운전 시간과 도착지 입력
3. 괘씸·감면 입력 — 타일과 분 입력
4. 정산 결과 — 받을 돈과 보낼 돈

## 3. 데이터 보안 양식

이 앱이 실제로 하는 것만 적는다. 위치·광고 식별자·계정·연락처는 쓰지 않는다.

| 질문 | 답 | 근거 |
|---|---|---|
| 데이터를 수집하거나 공유하나요 | **예** | 장소 검색어와 사용자가 고른 장소의 좌표가 우리 Worker를 거쳐 카카오·TMAP으로 간다 |
| 위치 | **아니요** | 기기 위치 권한을 요청하지 않는다. 좌표는 사용자가 목록에서 고른 장소의 것이다 |
| 개인 정보(이름·이메일·전화) | 아니요 | 멤버 이름은 폰에만 저장한다 |
| 금융 정보 | 아니요 | 금액은 폰에만 저장하고 결과 링크 안에만 들어간다 |
| 앱 활동(검색어) | **예 — 수집함** | 장소 검색어를 조회에 쓴다. 서버에 저장하지는 않지만 앱 밖으로 나가므로 수집으로 신고한다 |
| 앱 정보·성능(고른 장소 좌표) | **예 — 수집함** | 경로 조회에 쓴다. 기기 위치가 아니라 사용자가 목록에서 고른 장소의 좌표다 |
| 기기 식별자·광고 ID | 아니요 | 광고 SDK가 없다 |
| 데이터 암호화 전송 | 예 | HTTPS |
| 삭제 요청 방법 | 앱 삭제 | 서버에 사용자 데이터가 없다 |

**확정(2026-09-21): 검색어와 고른 장소 좌표를 "수집함"으로 신고한다.** 서버에 저장하지 않아도 앱 밖으로 나가기 때문이다. 신고 누락은 앱 정지 사유이고, 넉넉히 신고해서 받는 불이익은 없다.

"일시적 처리" 예외는 주장하지 않는다. 경로 응답을 6시간 캐시하기 때문이다(캐시 키는 반올림한 좌표를 비밀 값과 섞은 해시라 좌표 원문은 남지 않지만, 조회 결과 자체는 그 시간 동안 서버에 남는다). 장소 검색은 캐시하지 않지만, 두 값을 따로 신고해 헷갈리게 만들 이유가 없어 같이 신고한다.

폼에서 함께 고를 것: 전송은 암호화(HTTPS), 수집은 **선택 사항이 아님**(앱 기능에 필요), 삭제 요청 방법은 앱 삭제.

## 4. 개인정보처리방침 초안

페이지는 `apps/site/privacy.html`로 만들었고 Worker가 `/privacy`로 서빙한다. 실제 주소는 배포 때 정해진다(예: `https://<앱>.workers.dev/privacy`). 시행일과 문의 이메일은 배포 시 채운다.

1. **개요** — "오늘 운전 완료"는 로그인이 없고, 여행 기록을 서버에 저장하지 않습니다.
2. **폰에만 저장하는 것** — 여행 날짜·시각, 도착지 이름, 멤버 이름, 금액, 괘씸·결제 기록, 설정. 앱을 지우면 함께 사라지고 백업 기능은 제공하지 않습니다.
3. **서버로 전송하는 것과 이유**
   - 장소 검색어: 장소를 찾기 위해. 서버에 저장하지 않습니다.
   - 사용자가 고른 장소의 좌표: 거리·통행료·택시요금을 조회하기 위해. 캐시 키는 좌표를 비밀 값과 섞은 해시라 좌표 원문이 남지 않습니다.
   - 시·도 코드와 유종: 지역 평균 유가를 읽기 위해.
   - 사람 확인 토큰(Cloudflare Turnstile): 자동 프로그램의 남용을 막기 위해.
   - 위 값은 외부 조회 서비스(카카오모빌리티·카카오 로컬·TMAP·한국석유공사 오피넷)에 전달됩니다. 사용자 IP는 전달되지 않습니다.
4. **수집하지 않는 것** — 기기 위치, 연락처, 계정, 광고 식별자, 결제 정보. 광고를 넣지 않습니다.
5. **보관 기간** — 서버는 사용자 데이터를 보관하지 않습니다. 조회 응답 캐시는 최대 6시간이며 개인을 알아볼 수 없습니다. 오류 로그에는 오류 코드만 남깁니다.
6. **결과 링크** — 금액·이름은 링크 주소의 `#` 뒤에 담깁니다. 이 부분은 브라우저가 서버로 보내지 않습니다. 링크를 받은 사람은 앱 없이 볼 수 있으므로, 링크 공유 범위는 사용자가 정합니다.
7. **아동** — 만 14세 미만을 대상으로 하지 않습니다.
8. **권리와 문의** — 서버에 개인정보가 없어 열람·정정·삭제 요청 대상이 없습니다. 앱 삭제로 모든 기록이 지워집니다. 문의 이메일은 M6에서 정합니다.
9. **변경 고지** — 방침이 바뀌면 이 페이지에 날짜와 함께 올립니다.

## 5. 트랙 순서와 사람이 할 일

| 단계 | 하는 일 | 누가 |
|---|---|---|
| 1. 앱 만들기 | Play Console에서 앱 생성, 패키지명 `kr.driverlabor.app`, 기본 언어 한국어 | 사람 |
| 2. 서명 | Play 앱 서명 켜기, 업로드 키 등록 | 사람 |
| 3. 첫 빌드 | 릴리스 AAB 빌드(`bundleRelease`), 버전 `version.json`에서 올림 | 코드+사람 |
| 4. 내부 테스트 | 내부 테스트 트랙 업로드, 본인 기기로 설치해 정산·공유 확인 | 사람 |
| 5. 앱 콘텐츠 | 개인정보처리방침 URL, 데이터 보안 양식, 콘텐츠 등급 설문, 광고 없음, 대상 연령 | 사람 |
| 6. 클로즈드 테스트 | **개인 계정이면** 테스터 12명을 모아 14일 연속 참여. 조직 계정이면 생략 | 사람 |
| 7. 프로덕션 신청 | 등록정보·스크린샷 확정, 심사 제출 | 사람 |
| 8. 출시 후 | 오류 보고 확인, `versionCode` 올려 업데이트 | 사람+코드 |

- 6번이 일정의 대부분이다. 테스터 모집을 3번 단계와 같이 시작하는 것이 좋다.
- 업데이트는 심사를 거치므로, 계산이나 문구 수정도 릴리스 단위로 묶는다.
